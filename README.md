## 一、怎么打开 / How to open

双击 `index.html` 即可，**不需要装任何东西、不需要服务器**（纯静态、可离线、可拷 U 盘 / 发给别人）。

> 也可用本地服务器（分享给同事手机 / 投屏电脑时更稳）：
> `cd site && python3 -m http.server 8000` → 浏览器打开 `http://localhost:8000`

推荐浏览器：Chrome / Edge / Safari 最新版。设计基准 1920×1080，最小 1280×720。

## 二、这个站点做了什么 / What's inside

### 三个视图状态（不是三个页面）
| 视图 | 你看到 | 用来干什么 |
|---|---|---|
| **浏览** | 平面图 + 时间轴带 + 左右栏 | 讲单个时段：谁在哪、哪里挤 |
| **时间线** | 8 时段 × 4 类机器人泳道 | 横向比较「谁在什么时候忙」 |
| **对比** | 左右双地图 + 3 指标 + Δ | 给结论、做汇报 |

### 五个 P0（PRD §4.1）全部落地
- **F1 时段与时间轴**：T1–T8 胶囊、可拖游标、播放 / 暂停 / 步进 / 0.5–4× 速率，游标跨 8 时段连续推进
- **F2 楼层切换**：1F / 2F，切层保留时段与开关；2F 中庭挑空灰色斜纹不可通行
- **F3 冲突识别**：C1 空间 / C2 时间 / C3 设施，三级严重度，点开有「类型·持续·判定式·原因·3 条可执行建议」
- **F4 现状 / 提案对比**：A/B 双地图 + 冲突指数 / 通行代价 / 峰值密度 + Δ
- **F5 对象详情 + POV**：点机器人 / 冲突点 / 门 / 停靠点 / 空白处（最近视点）都出卡

### 三条对得上的数字（与 PRD / 高保真图完全一致）
- T5 双层合计冲突指数 **A 0.21 → B 0.19（−13%）**
- 大厅 → 2F：**现状「不可达」→ 提案 61s**
- 峰值密度：**1.8 → 1.5 人/m²**（> 1.5 标红）
- 结论写法保留：「B 使 2F 可达，但把 1 处高风险从餐厅门口转移到廊桥口」

### 硬规则（PRD §7.1）在代码里是真的在跑，不是贴纸
- 门通行判定：`净宽 − 2×安全余量 < 机器人宽度 → 不可通行`（改参数，判定立刻变）
- 常闭防火门 / 禁行区域 → 一律不可通行，点开有原因
- 2F 现状 A 的机器人数 = 0，并给出「为什么」的说明卡（这是结论，不是 bug）
- 所有数字带来源标签：假设 / 文献 / 设计 / 待校准；没有实测就写「待确认」
- 冲突指数 = Σ(冲突点 × 严重度权重 3/2/1) ÷ 时段时长，权重可在参数抽屉里改

## 三、怎么编辑 / How to edit（这就是「可以编辑」的两层）

### 第 1 层：在网页上直接改（给非技术同事）
1. 点顶栏 **「编辑」**，地图出现蓝色虚线框 + 候选停靠位（虚线圆）
2. **拖**：机器人 / 冲突点 / 候停点 / 分区标签都可以直接拖
   - 停靠点会自动吸附到候选位；放到非法位置会**明确告诉你哪里不行**
     （不在楼板范围 / 距门不足 1.5m / 挡 1.2m 主通道 / 离充电桩 > 30m / 与既有停靠点 < 3m）
3. **改属性**：点任意对象 → 右栏出现表单
   - 机器人：编号、类型、状态、任务链、路线 `d`、在场时段
   - 冲突点：类型、严重度、出现时段、持续秒数、坐标、原因、3 条建议
   - 门：净宽、类型、是否常闭、来源（改成「实测」后界面上的「待确认」会自动消失）
   - 停靠点：名称、坐标
4. **增删**：地图右上角 `+ 机器人` / `+ 冲突点` / `+ 停靠点`；表单底部有删除
5. 改动**自动存本地**（localStorage），刷新不丢
6. 顶栏 `⋯` → **导出 JSON** 把这份数据带走；**导入 JSON** 回填；**恢复默认** 一键还原

### 第 2 层：改源文件（给开发 / 想批量改的人）
所有内容都在 **`js/data.js`** 一个文件里，改完刷新即可，无需构建：

| 想改什么 | 改哪里 |
|---|---|
| 时段名称 / 起止时间 / 人流特征 / 峰值密度 / 通行时间 | `SLOTS` |
| 机器人路线、在场时段、任务链 | `FLOORS['1F'].robots.A / B` |
| 冲突点位置、严重度、原因、建议 | `FLOORS[...].conflicts.A / B` |
| 门表（净宽 / 类型 / 常闭 / 来源） | `FLOORS[...].doors` |
| 候停点 / 候选位 / 充电桩 / 热力 / 人流箭头 / 分区标注 | `FLOORS[...]` 同名数组 |
| 参数默认值 | `PARAMS` |
| POV 视点位置与说明 | `POVS` |
| 硬规则文案 | `RULES` |

> 门 / 冲突 / 机器人的坐标**单位 = 底图 CAD 像素**（1F 1413×996，2F 1184×1096），
> 与 `js/map.js` 的 `viewBox` 同坐标系，改坐标就是改像素位置。
> 米制校验（1.5m 距门、30m 充电桩…）用参数 `pxPerM`（默认 20）换算，比例待校准。

## 四、目录结构 / Structure

```
site/
├── index.html          入口（双击它）
├── css/style.css       设计系统（配色 / 字号 / 组件，取自 PRD §11）
├── js/data.js          ★ 全站唯一数据源（可编辑层）

├── js/app.js           三视图 / 播放 / 指标 / 交互 / 参数抽屉
├── js/edit.js          编辑模式：拖动 / 表单 / 增删 / 吸附与校验

    ├── 1F.png          Building 2 · 1F CAD 底图（1413×996）
    └── 2F.png          Building 2 · 2F CAD 底图（1184×1096）
```

数据流：`data.js` → `map.js`（画）＋ `app.js`（算/交互）→ `edit.js` 改 `data.js` 的内存对象 → `localStorage` 持久化。

## 六、给学生用 / For students

打开链接就能用，第一次会自动弹一个 **3 步引导**（之后不再弹；`⋯ → 新手引导` 可再看）。

**三条练习路线（建议按顺序）**
1. **找冲突**：顶栏选 `T5 午餐`，在 1F 图上找出红色的最高严重度冲突点 → 点开，说出「为什么堵」和「3 条怎么改」。
2. **解释结论**：切到 `2F` + `现状 A`，数一下有几台机器人；说明为什么是 0（这是结论，不是加载失败）。
3. **给结论**：点 `对比`，说出 A 和 B 的**一个量化差异**（哪个指标、涨还是跌、多少）。

**操作提示**
- 地图太小看不清 → 用地图右侧的 `＋` 放大到 150–200%，放大后可滚动 / 触控板双指平移；`适应` 一键回原大小。
- 冲突点 / 机器人 / 门的**可点范围比看到的大**，点不准就点它附近一圈。
- 键盘：`1` / `2` 换楼层，`空格` 播放 / 暂停，`←` / `→` 步进，`Esc` 取消选择。

**关于「编辑」**
- 学生的编辑只存在**这台电脑的这个浏览器**里（localStorage），不影响别人，也不会上传。
- 下一个人接着用同一台电脑 → `⋯ → 恢复默认数据`，立刻回到干净的初始状态。
- 想直接收掉编辑入口进课堂 → 用只读链接（见下）。

**URL 参数（可直接发给学生）**

| 参数 | 作用 | 例子 |
|---|---|---|
| `ro=1` | 只读课堂模式：隐藏「编辑」、不读写本地编辑 | `index.html#ro=1` |
| `play=1` | 打开即自动播放一整天 | `index.html#play=1` |
| `z=1.5` | 初始放大到 150%（范围 1–2.5） | `index.html#z=1.5` |
| `view=compare` / `timeline` / `browse` | 直接进某个视图 | `index.html#view=compare` |
| `floor=2F` `slot=T5` `variant=B` | 直接定位楼层 / 时段 / 方案 | `index.html#floor=2F&slot=T5&variant=B` |
| `sel=conflict:②` | 直接选中某个冲突点（`robot:R1` / `door:1F-D05` 同理） | `index.html#sel=conflict:①` |

参数可叠加，用 `&` 连接：`index.html#view=compare&floor=2F&slot=T5&variant=B&z=1.5`

## 七、机器人路线：目前是示意 / Route layer is schematic

2026-11-03 修正。原先 14 条 `d` 路径继承自高保真图的目测锚点，
**会明显穿墙**（安保环线斜穿东北墙带、导览起点落在墙体里）。

**已做的止血（临时方案 B）**
- 用「软化障碍代价场 + 最小代价路径」重算全部 14 条路线：
  锚点改取人流 / 冲突点 / 热度中心这类本来就落在通道上的位置，
  墙体代价设为极高、空地代价低，路径自然绕开墙密集处。
- 定量校验（沿路径每 1.5px 采样，统计落在强墙像素上的比例）：

  | | 平均 | 最严重的一条 |
  |---|---|---|
  | 修正前 | **24.5%** | 42.6%（2F 安保） |
  | 修正后 | **1.18%** | 2.7% |

- 前后对比图见项目根目录 `路线校验_1F_前后对比.png` / `路线校验_2F_前后对比.png`。

**必须向学生说明的限制**
> 这些路线仍是**示意**，不是「真实可通行路径」。
> 机器人在图上只是「尽量不穿墙」，并没有跑在走廊中心线上。

原因：PRD §10.1 第④步「建网：沿可通行走廊生成中心线（节点—边）」尚未做。
1F 底图里有放射状虚线（视线）、柱网引线和成排家具，把开敞大厅在像素层面切碎，
自动提取的「最大连通可通行区」只有 0.5%，**无法从这张光栅图直接生成可靠路网**。

界面上已在四处标出：图例「⚠ 机器人路线＝示意」、地图顶部提示条、
左栏图层名与说明、机器人详情卡的「路线」一行。

**彻底解决（V1.1 / 方案 A）**：手工定义 1F / 2F 各 10–15 个走廊节点并连成边，
机器人沿图走；之后「停靠点吸附」「通行时间」才有计算依据。
